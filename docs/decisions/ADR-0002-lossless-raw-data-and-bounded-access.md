# ADR-0002：无损原始数据与有界访问

- 状态：已接受。
- 日期：2026-10-02（UTC+8）。
- 适用阶段：数据模型与访问路径设计；本记录不定义生产类型或接口。

## 背景

Phase 0 发现 JSON.parse 会舍入真实 ID/哈希，SQLite signed INTEGER 不能覆盖全部数值，且多个物理记录可共享一个 SkillID。大文件与巨大嵌套项还要求记录级资源边界。

## 决定

- 保留原始 JSON 类型、无损数值词法与源出处；123 与 "123" 必须可区分。
- 原始数值 token 未经安全性证明不得经过 JavaScript number，大整数 ID/哈希不得静默舍入；不能假设 SQLite signed INTEGER 可保存所有标识符。
- 区分物理记录地址与 Dataset Contract 定义的逻辑身份。物理地址可由源文件与 JSON Pointer/等价位置确定，逻辑身份可由显式单字段、复合字段、对象键或其他确定性选择器定义。
- 不假设一个 ID 字段对应一个物理记录，不自行合并重复 ID 或选择默认版本/等级。
- 接受混合访问方向：小且安全的文件可有界完整解析；大或精度敏感文件采用流式和/或索引访问。
- Renderer 仅接收有界查询、选定记录或有界源片段，默认不接收整份巨大数据文件。巨大原文是数据源，不是编辑器/Svelte 状态中的整文件文档。

## 后果

生产表示必须同时支持类型、词法与出处。精度检查不只按文件大小决定；流式也不保证超大单条记录或 scalar 无限制内存。记录选择与源片段边界需要专门验证。

## 推迟的方案与细节

不设计 RawScalar、正式记录模型、Dataset Contract 语法、数据库 schema 或源字节范围格式。不设置永久文件大小阈值，不声称流式普遍更快。numberAsString 是实验便利表示，不能直接成为生产类型；原始偏移回读仍未验证。
